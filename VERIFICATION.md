# Verification boundaries

- **Git and policy identity:** Use disposable repositories with real commits and independent Git common directories. A change review must load project rules from the comparison base even when the reviewed head and the caller's checkout contain different text. Test exact commit inputs, changed paths, selected files, and clean/dirty checkout disposition (including ignored files and unexpected sibling files) through the supported run entry point. Mocking Git cannot establish these guarantees.
- **Reviewer behavior:** Inject a reviewer only at the Pi SDK boundary for routine tests. Assert each rule gets an independent assignment, that one failure preserves other reports and exits incomplete, and that dirty or unsettled reviewer activity is reported and preserves the checkout; no new sessions start after uncertainty is established, and the chosen concurrency cap holds during settlement. Tests need not call a paid model. Check the config model and thinking-level defaults, CLI overrides (including concurrency), invalid concurrency, missing model, invalid level, and unknown Pi model through the run entry point. Changes to Pi model selection, effective thinking level, resource loading, compaction, or tool availability need a focused SDK session check, including the exact `read`/`bash` reviewer tool set. For extension selection, check that a chosen Pi package extension loads while ambient global and repository extensions and package skills do not; a fabricated reviewer cannot establish those SDK behaviors.
- **Executable and package:** Check the built `by` process when changing argument parsing, stdout, exit status, build, or package layout. A source import alone does not prove the shipped entry point works.

The pinned Biome, Oxlint/Effect, test, and build scripts are the ordinary static checks; run the applicable scripts rather than maintaining a second list here. Shell-capable reviewers are cooperative, not isolated from the host. Do not run live-review checks against an unrelated checkout, and do not delete a worktree whose ownership and cleanliness are unproven.
